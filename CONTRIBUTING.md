# Работа с общим кодом

GitHub — источник актуального кода. На каждом компьютере используйте отдельную локальную рабочую копию вне синхронизируемых облачных папок.

1. Проверьте `git status`. Сохраните незавершённые изменения отдельным коммитом или stash; не перезаписывайте их.
2. На чистом рабочем дереве выполните `git fetch origin`, переключитесь на `dev` и получите изменения: `git pull --ff-only`.
3. Все текущие изменения делайте в `dev`. `main` — стабильная ветка; напрямую в неё не коммитьте и не отправляйте правки.
4. Меняйте общий код в `source/`. Различия ОС — в `platform_support.py` и `packaging/`.
5. Выполните `python scripts/check.py`, посмотрите diff и состояние Git.
6. Сделайте осмысленный commit, затем `git push origin dev`.
7. Дождитесь успешных GitHub Checks на Windows и macOS именно для предлагаемого коммита. При необходимости выполните нативные проверки сборки, установщика и реального поведения. Ожидающая или неуспешная проверка не разрешает слияние.
8. После всех нужных проверок перенесите `dev` в `main`, предпочтительно через pull request `dev` → `main`. После слияния вернитесь в `dev` для дальнейшей работы.

На обоих компьютерах рабочая ветка — `dev`. Перед переходом на другой компьютер отправьте коммиты в `origin/dev`, а на втором получите их через `git pull --ff-only`. Если Git сообщает о расхождении веток, разберите различия и разрешите конфликты без потери чужой работы; не применяйте force-push.

Коммиты и push выполняются явно после проверки результата. Установленные приложения не обновляются автоматически от коммита: для распространения нужны новые сборки.

Не отправляйте cookies, профили браузеров, пароли, SSH-ключи, `.env`, временные видео и локальные логи. Не коммитьте `.venv`, `work`, `outputs` или `.runtime`.
