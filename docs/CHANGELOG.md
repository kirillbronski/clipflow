# Текущие изменения — 2.0.0 acceptance candidate

- Новый общий Qt-интерфейс, тёмная/светлая темы и фирменные акценты площадок.
- Фиолетовая flow-иконка в приложении и поставках обеих ОС.
- Исправлены обрезанные подписи режимов; batch-действие скрывается в настройках/аккаунтах.
- Instagram раскрывает все параметры без внутреннего скролла; малое окно прокручивает основную страницу.
- Имена YouTube/GetCourse различают media identity/качество даже при одинаковых заголовках и усечении. Instagram сохраняет01.mp4/01.txt.
- Повтор коллекции восстанавливает отменённые/ошибочные дочерние загрузки и удалённые результаты; активные задания не дублируются.
- Видимые кнопки массовой отмены и очистки всех площадок; подтверждение с optional удалением файлов, per-ID consent и ожиданием worker ACK.
- Обновлены README, screenshots и native/package verification. Личные/live ограничения остаются явными.

# Изменения ClipFlow

## 1.8.7

- Windows: восстановлена иконка ClipFlow в заголовке окна; цвет соответствует активному сервису. Нативная иконка macOS не изменяется.
- Windows: сборка исключает DLL посторонних инструментов из PATH, предотвращая сбой запуска встроенного окна входа.

## 1.8.6

- Ссылки на профиль Instagram разворачиваются в очередь постов и Reels без дублей, с лимитом 10/50/100 или всеми публикациями; папки постов обязательны для этого режима. Отмена прерывает ожидание, ошибки доступа/ограничения не выдаются за успешный пустой результат.

- MP4, MKV и WebM доступны для YouTube, Instagram и GetCourse. MKV/MP4 перепаковываются без перекодирования, WebM при необходимости кодируется в VP9/Opus.
- В Instagram добавлен сохраняемый переключатель «Папка для каждого поста», включённый по умолчанию и независимый от папки автора.
- Папка поста содержит дату публикации (если известна), короткое описание и уникальный код; посты без описания не смешиваются.
- В отдельной папке элементы имеют имена `01.mp4`, `02.jpg` и парные `01.txt` / `02.txt` (или MD). Номера соответствуют оригинальному порядку даже после фильтрации.
- Повторная загрузка использует те же пути; для итоговых видео учитывается выбранное расширение.

## 1.8.5

- Общая обработка вставки для YouTube, Instagram и GetCourse: кнопка, горячие клавиши и контекстное меню. Windows использует Unicode-буфер обмена; на macOS поддержаны обе кнопки контекстного меню и Control-click. Сочетания редактирования поддерживают русскую раскладку.
- Instagram: переключатель «Папка с ником автора», включён по умолчанию. Медиа и описания сохраняются в `Instagram/ник/`; при отключении — в `Instagram/`. Если метаданные не содержат пригодного ника, используется `Unknown author`.
- Выбор папки автора сохраняется в настройках и фиксируется отдельно для каждого задания.
- Поле ссылки очищается после получения метаданных и начала скачивания. Новая введённая ссылка не удаляется событием от предыдущего задания.

Установленные приложения обновляются только после сборки и установки; изменение исходников само по себе их не обновляет.

## 2.0.0 — T16 Windows candidate

Единственный Qt runtime, parity mapping и удаление legacy Tk/scripts; реальная измеренная скорость передачи и сохранение byte counters на финальном hook. Обновлены архитектура/тесты/документы. Mac acceptance выделена в открытый T16a; candidate не означает завершённый межплатформенный выпуск.

## Разработка — единый стиль кода (без новой версии)

- Весь код отформатирован ruff (100 символов, одинарные кавычки); правила E/W/F/I/B/UP/SIM проходят, `scripts/check.py` и CI проверяют стиль перед тестами. Поведение не менялось: дерево разбора всех файлов совпадает, тексты интерфейса и палитры сверены снимком.
- Добавлены тесты логики рабочих потоков (ошибки проверки качества, подгрузка имён, итог задания, частота прогресса): coverage.py не видит тела QThread, поэтому эта логика раньше не измерялась.

## 2.0.4 — названия в очереди сразу

- Задания из плейлиста YouTube, урока GetCourse и профиля Instagram сразу показывают название (трек, урок, первая строка подписи поста или код), а не «Новая загрузка». Задание плейлиста показывает название плейлиста.
- Ожидающие видео YouTube (все форматы, включая одиночные ссылки) в фоне получают будущее имя файла, например «Пропаганда - Мелом»: по одному запросу метаданных на трек, строго по одному и с паузой 1 с. Ошибка оставляет предварительное название и не повторяется в цикле. Instagram и GetCourse в фоне не опрашиваются.
- При старте загрузки YouTube строка показывает имя будущего файла, при совпадении имён — итоговое « (n)».
- Названия сохраняются в базе очереди и переживают перезапуск; на ключи дедупликации не влияют; старые записи читаются.
- Тест бюджета пути больше не зависит от ОС: CI 2.0.3 на Windows упал только на нём (корень `D:\` длиннее на 2 символа), продуктовый код не затронут.

## 2.0.3 — имена «Исполнитель - Название», нумерация по желанию

- Файлы YouTube (MP3 и видео) называются «Исполнитель - Название», когда YouTube отдаёт исполнителя и трек; иначе — название ролика. Хеш в квадратных скобках убран. Папка плейлиста — «Название [ID]».
- Нумерация «001 - …» только по галочке «Нумеровать треки плейлиста» (по умолчанию выключена, сохраняется в настройках YouTube).
- Защита от совпадений вместо хеша: ID и качество записываются в тег comment файла (`clipflow:…`). Готовый файл с тем же тегом переиспользуется, другой трек с тем же именем получает « (2)»; публикация не перезаписывает чужой файл. Временные файлы загрузки различаются по ID.
- Формат в списке называется просто «MP3».
- Старые файлы со старыми именами не переименовываются; ключи дедупликации прежних заданий и сохранённые настройки читаются без изменений. Instagram и GetCourse не затронуты.

## 2.0.2 — исправление загрузки MP3 и имени папки плейлиста

- MP3 с YouTube и YouTube Music снова скачивается. Причина HTTP403: метаданные probe сохраняли выбор yt-dlp по умолчанию (`requested_formats` видео+аудио), и при повторной обработке для MP3 загрузчик шёл по устаревшему набору форматов. Перед загрузкой этот результат прежнего выбора теперь отбрасывается. MP4 не затрагивался: новый выбор видео+аудио перезаписывал поле.
- Папка плейлиста с названием — ровно `Название [ID]`, например `Sound City [PLO5Q7HxgkOYo]`, без служебного суффикса регистра. Без названия сохраняется прежнее имя по ID.
- Живая проверка публичного плейлиста PLO5Q7HxgkOYo (Sound City, 49 позиций): трек001 скачан через код приложения, MP3 audio-only 320000 бит/с. Прежняя запись 2.0.1 о «HTTP403 без авторизации» ошибочна — это был описанный выше дефект.

## 2.0.1 — YouTube Music MP3

Ссылки с точным music.youtube.com сохраняют происхождение и принудительно создают MP3-задания: одиночный трек, плейлист, batch и дочерние задания очереди/restart/retry. Виджет показывает заблокированный MP3, обычный YouTube сохраняет предыдущий ручной формат даже после изменения папки в Music-режиме.

Папки плейлистов начинаются с настоящего title, затем portable ID; позиции001 сохранены. Старые SQLite записи без title читаются; title не меняет ключ дедупликации.
