# ClipFlow: передача проекта агенту Codex на Windows

Состояние на 9 октября 2026 года. Планируемый первый запуск на Windows — 12 октября 2026 года. Этот файл можно передать агенту целиком. Это инструкция от владельца проекта для продолжения работы; актуальные исходники и инструкции всегда нужно дополнительно получить из GitHub.

## Задание агенту при первом запуске

Подготовь на этом Windows-компьютере локальную рабочую копию общего проекта ClipFlow, настрой Python-окружение, выполни проверки и проверь запуск приложения из исходников. Сначала прочитай этот документ и актуальный `AGENTS.md` репозитория. Продолжай самостоятельно в рамках подготовки проекта; в конце сообщи путь, ветку, коммит, результаты проверок и оставшиеся ограничения. Не ограничивайся описанием плана.

Не изменяй прежний Windows-проект на Google Диске. Не устанавливай новую сборку поверх приложения и не публикуй новый релиз только на основании этого документа: сборка и установка — отдельный следующий этап. Если возникнут несовместимости общего кода с Windows, исследуй и исправь их в общей кодовой базе, сохраняя поведение macOS, и покажи проверенный результат.

## Что теперь происходит с проектом

ClipFlow — настольное Python-приложение для скачивания материалов YouTube, Instagram и GetCourse. Раньше Windows и macOS имели отдельные папки исходников. Теперь актуальный код объединён в **один репозиторий**:

**https://github.com/kirillbronski/clipflow**

- Рабочая ветка для всех изменений на обеих ОС: `dev`. Стабильная ветка: `main`; слияние только после всех необходимых проверок.
- Репозиторий публичный, владелец — `kirillbronski`.
- Главный файл приложения: `source/clipflow.py`. Старое имя `downloader.py` больше не является точкой входа общего проекта.
- Удобная точка запуска из корня: `run.py`.
- Версия в `source/version.py`: на момент передачи `1.8.4`; при начале работы сверь актуальное значение.
- Это одна кодовая база и две нативные сборки, а не две независимо развиваемые программы.

Общие интерфейс, очередь, обработка прогресса и скачивание меняются один раз в `source/`. Системные отличия сосредоточены преимущественно в `source/platform_support.py` и `packaging/`: пути данных, шифрование, сочетания клавиш, системные действия и упаковка. Не создавай новый форк исходников «для Windows» и не копируй исправления вручную между двумя приложениями.

**GitHub не обновляет установленные EXE/APP автоматически.** Коммит меняет исходники. На другом компьютере нужно получить его через Git, а для обновления установленной программы — собрать и установить новую версию.

## Получить проект на Windows

Сначала проверь установленный Git, существующие рабочие копии и занятость целевой папки. Не перезаписывай чужие или незакоммиченные изменения. Следующие команды — PowerShell, для отсутствующей целевой папки:

```powershell
git --version
$clipflowParent = Join-Path $HOME 'PycharmProjects'
$clipflowRoot = Join-Path $clipflowParent 'ClipFlow'
New-Item -ItemType Directory -Force $clipflowParent | Out-Null
git clone --branch dev https://github.com/kirillbronski/clipflow.git $clipflowRoot
Set-Location $clipflowRoot
git status --short --branch
git remote -v
git log -1 --oneline
```

Публичный репозиторий можно скачать по HTTPS без входа. Для отправки изменений нужна авторизация владельца на **этом** компьютере. SSH на Mac уже проверен, но это не означает, что он настроен на Windows.

Проверь существующий доступ Windows без чтения приватных ключей. Если SSH настроен для нужного аккаунта, можно использовать:

```powershell
ssh -T git@github.com
git remote set-url origin git@github.com:kirillbronski/clipflow.git
```

Успешный ответ SSH называет аккаунт, но команда может завершиться кодом 1, поскольку GitHub не предоставляет shell. При первом соединении проверь подлинность хоста, не отключай проверку. Если доступа нет, подготовку и локальные проверки продолжай через публичный HTTPS; для push помоги владельцу пройти обычную авторизацию GitHub. Не проси присылать пароль, токен или приватный SSH-ключ в чат и не переноси приватный ключ с Mac.

Перед первым коммитом проверь `git config user.name` и `git config user.email`. Используй имя владельца и его GitHub noreply-email; в Mac-копии локально указан `kirillbronski@users.noreply.github.com`. Не публикуй личный email без согласия. При необходимости настрой автора только для этого репозитория.

Если рабочая копия уже существует: сначала `git status`, проверь remote, ветку и локальные изменения. На чистом дереве переключись на `dev` и получи обновления через `git pull --ff-only`. Если локальной `dev` ещё нет: сначала `git fetch origin`, затем `git switch --track origin/dev`. Не применяй `reset --hard`, принудительный push или автоматическое удаление рабочего дерева.

## Настроить запуск

Прочитай `docs/DEVELOPMENT.md`. Нужны Python **3.12 x64 с Tkinter**, FFmpeg, FFprobe и Node.js. Проверь, что они уже установлены, прежде чем устанавливать повторно. Зависимости Python перечислены в `requirements.txt`.

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -c "import tkinter; print(tkinter.TkVersion)"
ffmpeg -version
ffprobe -version
node --version
.\.venv\Scripts\python.exe run.py
```

Активация `.venv` и изменение PowerShell ExecutionPolicy не требуются. Команды выполняются из корня проекта. Не пересоздавай уже исправное окружение без необходимости.

FFmpeg/FFprobe/Node можно найти через PATH либо положить настоящие `ffmpeg.exe`, `ffprobe.exe`, `node.exe` в `.runtime/windows/bin/`. Есть переопределение `CLIPFLOW_BIN_DIR`. Для упаковки нужны настоящие бинарники, а не Chocolatey shim-файлы. Локальные бинарники в Git не добавляются.

| Файл или папка | Что делает |
|---|---|

| `source/download_events.py` | Обработка событий загрузки |
| `source/instagram_media.py` | Instagram-медиа, фотографии и описания |

| `source/youtube_session.py`, `source/instagram_session.py` | Раздельные защищённые сессии |
| `source/_internal/customtkinter` | Встроенный CustomTkinter с исправлением переключения вкладок |

Сохрани сделанные исправления: переключение цветовых тем без промежуточных перерисовок; отсутствие мигания статуса загрузки из-за частых событий; изоляция ошибок одного задания от другого; ограничение частоты обновления прогресса. Не заменяй встроенный CustomTkinter обычной pip-версией без анализа локального исправления.

Instagram в README описан как скачивание **открытого контента без входа**: Reels, посты, фото, карусели, фильтры видео/фото, описания TXT/MD. Код входа, хранения и применения сессии сохранён, но элементы входа Instagram скрыты в панели и меню аккаунтов. Не включай их и не обещай готовую авторизацию без отдельной задачи и реальной проверки входа. Ограничения Instagram могут мешать скачиванию даже отдельных открытых публикаций.

## Данные пользователя: не ломать и не публиковать

- Windows-настройки и GetCourse: `%LOCALAPPDATA%\YouTubeDownloader` — историческое имя намеренно сохранено.
- Windows-сессии YouTube/Instagram: `%LOCALAPPDATA%\ClipFlow`.
- macOS: `~/Library/Application Support/ClipFlow`, защита через Keychain.
- Windows-защита: DPAPI текущего пользователя; сохранённый формат совместимости нельзя менять без миграции.
- Тестовый профиль задаётся `CLIPFLOW_DATA_DIR`. Автоматические проверки изолированы от реальных аккаунтов.
- Не коммить cookies, профили браузеров, пароли, ключи, `.env`, загруженные медиа, `.venv`, `.runtime`, `work` или `outputs`.

## Проверки на этом Windows-компьютере

```powershell
.\.venv\Scripts\python.exe scripts/check.py
```

Проверки охватывают интерфейс трёх сервисов, очередь и статусы, действия с файлами, Instagram-фото/описания, платформенные пути и шифрование, частоту прогресса. Это offline-проверки с тестовыми данными и локальными ответами; они не доказывают работоспособность всех реальных сайтов.

Проверь также обычный запуск `run.py` и интерфейс Windows. Для реального скачивания используй согласованный открытый контент и отдельную тестовую папку. Сборка требует отдельной проверки упакованной программы и окон входа. Не используй настоящие сессии для автоматических тестов.

## Следующий этап: сборка Windows

Когда владелец поручит сборку, прочитай `docs/BUILDING.md`. Для установщика нужен Inno Setup 6:

```powershell
.\.venv\Scripts\python.exe scripts/build.py
```

Результат: `outputs/ClipFlow-Setup-VERSION.exe` и `outputs/ClipFlow-VERSION-Windows-x64-portable.zip`. Для одной portable-сборки есть `--portable-only`. Portable ZIP распаковывается целиком.

AppId прежнего Windows-установщика сохранён для обновления поверх приложения. Перед установкой проверь новую сборку и сохранность настроек; завершение работающего приложения согласуй с текущими загрузками. Не удаляй пользовательские данные. Версию для нового релиза обновляй в `source/version.py`, а не независимо в двух ОС.

Windows EXE собирается на Windows, macOS DMG — на Mac. Общий коммит может использоваться для обеих сборок, но проверка одной ОС не заменяет проверку другой. Готовые файлы хранятся отдельно от Git, в Drive и/или GitHub Releases после подготовки релиза.

## Как дальше менять программу с двух компьютеров

1. Начинай с `git status`, чтения `AGENTS.md`, `git fetch origin` и получения актуальной чистой `dev` через `git pull --ff-only`.
2. Все изменения делай в `dev`. Прямые коммиты и push в `main` запрещены этим рабочим процессом.
3. Меняй общий код. Системную особенность оформляй через платформенный модуль, сохраняя поведение другой ОС.
4. Проверь результат, `git diff`, отсутствие секретов и случайных файлов.
5. Сделай понятный commit и `git push origin dev` при доступной авторизации.
6. Дождись успешных GitHub Checks на Windows и macOS для точного коммита, который предлагается слить. Выполни необходимые нативные и ручные проверки по характеру изменения. Только затем внеси `dev` в `main`, предпочтительно через pull request; следуй текущему `CONTRIBUTING.md`. Если создаёшь PR в Codex, прикрепи его к чату средствами приложения. Проваленные или ожидающие проверки не обходи.
7. Для дальнейшей разработки оставайся в `dev`. На втором компьютере также получи обновлённую `dev` через Git. Не копируй всю папку поверх другого клона.

Коммиты не происходят сами при сохранении файла. Агент должен явно проверять, коммитить и отправлять изменения согласно задаче. Перед переходом на другой компьютер сохрани текущую работу коммитами в `dev`, отправь её в `origin/dev` и укажи состояние проверок в передаче. Непроверенные изменения остаются в `dev`; в `main` они сами не появятся.

Репозиторий публичный, но собственный код ClipFlow опубликован **без открытой лицензии**. Не добавляй MIT или другую лицензию без решения владельца. Сохраняй лицензии сторонних компонентов. Посторонние не получают право записи в основной репозиторий только потому, что он публичный.
