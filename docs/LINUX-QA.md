# Linux: ручная приёмка

Поддерживаемые цели: Ubuntu 22.04+ x86-64, Ubuntu 24.04+ ARM64 и Fedora 40+ (обе архитектуры). Пока строки ниже
не заполнены, ручная приёмка Linux **не выполнена**. Результат CI и проверка
установщика на тестовом приложении не заменяют проверку готового ClipFlow.

Для Ubuntu ARM64 в Parallels на Mac используйте официальный ARM64-образ Ubuntu,
создайте отдельную VM и получите кандидат нужной архитектуры из GitHub Actions
`Build native Qt candidates`. Для Fedora используйте x86_64-кандидат.
Сверьте файл с `SHA256SUMS.txt`: `sha256sum -c SHA256SUMS.txt`.
Артефакты до подтверждённого успешного CI не считаются проверенными.

Установка без root: `~/.local/opt/ClipFlow`. Данные в абсолютном
`$XDG_DATA_HOME/ClipFlow`, иначе `~/.local/share/ClipFlow`. `CLIPFLOW_DATA_DIR`
имеет приоритет для тестов. Удаление программы не должно удалять эти данные.
Пустой каталог установки может остаться после удаления; посторонние файлы
в каталоге установки не удаляются рекурсивно.

Для CLI-обновления QtIFW нужны одинаковые пути в `--root PATH` и
`ClipFlowUpgradeTarget=PATH`; графический мастер использует выбранный каталог.
Обновление выполняется только для установки с маркером `clipflow-install.txt`.

Автопроверка: `python scripts/check.py`; реальный Secret Service — отдельный
`dbus-run-session` с тестовым keyring и `CLIPFLOW_SECRET_SERVICE_NATIVE=1`.
Нативная сборка: `python scripts/build.py`, portable без QtIFW — `--portable-only`.
`python scripts/linux_tools.py --arch x86_64 --dest .runtime/linux` получает
закреплённые инструменты; для ARM64 используйте `aarch64`. Сборка отказывает,
если какой-либо ELF требует GLIBC новее 2.35 для x86-64 или 2.39 для ARM64.
